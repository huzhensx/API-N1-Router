## 📖 项目简介

本程序是一个**API多合一路由器**，可将多个上游 LLM 提供商（如 NVIDIA、商汤 SenseNova、魔搭 ModelScope 等）聚合为一个统一的 OpenAI 兼容接口。你在任何支持 OpenAI 格式的第三方工具（WorkBuddy、ChatBox、NextChat、SillyTavern、Dify 等）里填入本网关的地址和密钥，即可：

- 自动在多个上游渠道间**智能轮询**，单个渠道挂了无感切换
- 实时**监控**所有模型的健康状态、可用率、延迟
- 自定义**路由组**，按需调度模型
- 统计 **Token 消耗**

程序提供**exe**和\*\*网页版（自行部署）\*\*两种使用方式。

## 💡 API多合一路由器有什么作用？

绝大多数主流 LLM 提供商都提供**免费额度**（如 NVIDIA 每月免费调用次数、魔搭、商汤 等），但单个渠道的免费额度往往很快用完。

本网关的做法是：**把你所有的免费渠道聚合成一个 OpenAI 兼容入口**——


| 你的多个API渠道          | 网关做的事         |
| ------------------ | ------------- |
| NVIDIA 免费额度        | 自动轮询          |
| 商汤 SenseNova 免费额度  | 额度用完 → 无感切下一个 |
| 魔搭 ModelScope 免费额度 | 渠道故障 → 自动熔断跳过 |


**多个API渠道额度叠加 + 智能切换 = 你几乎永远有可用的免费模型**，这就是"无感限额"的来源。

> ⚠️ 前提：你需要自行注册各提供商账号并获取各自的免费 API Key，网关只负责聚合与调度，不提供密钥。

## ✨ 功能特性

### 📊 实时监控

- 展示所有上游模型健康状态、SLA 可用率、平均/极速/最慢延迟、探针次数
- 模型名旁的状态点代表**最近检测/使用**结果：🟢 正常 / 🔴 异常 / ⚪ 尚未使用
- 启动时自动巡检 1 次了解初始状态，之后靠**实际转发请求被动更新**健康状态（转发成功/失败即同步）；后台探活**只针对已停用（熔断 / 拉黑）的组合**，健康组合一个探测请求都不发，尽量避免触发上游限流；可点右上角"立即检测"手动全量检测
- 支持按可用性、提供商、关键词筛选

### 📏 上下文长度

- 直接点击监控表格"上下文窗口"列的数字即可**行内修改**，回车保存、Esc 取消
- 修改值写入 `models_meta.json` 持久保留，优先级高于上游返回的元数据
- 输入非法值或请求失败会自动还原原值，编辑过程不影响表格其余部分刷新

### 🔀 路由配置

- 创建自定义路由组并勾选成员模型，每个模型旁显示上下文长度
- 客户端 `model` 字段填路由组名即命中（如 `1m`、`256k`、`主力`、`备用`）
- 网关在组内按可用率/延迟加权择优
- 路由组创建后自动出现在"输出模型"列表

### ⚙️ 模型管理

- 每个提供商支持：编辑连接信息、勾选启用的模型、删除；卡片**右上角**另有 **⠿** 把手，可**拖动重排上游顺序**（见下方「上游排序」）
- 添加提供商时自动从上游拉取可用模型列表
- 点提供商卡片上的 **⚙️ 模型** 按钮打开模型管理窗口时，会**自动刷新一次**远端模型列表；搜索框右侧另有 **🔄 刷新模型列表** 按钮可随时手动刷新
- 模型管理窗口按**并集**展示：上游 `/models` 返回的模型 ∪ 已保存的模型
    - 上游列表里**不存在**的条目（手动添加的、或上游已下架但你想继续留着的）**照常列出、保存后原样保留**，名称以**红色**标注
    - 状态栏会给出计数：`共加载了 N 个模型 · M 个不在上游列表（红色标注，保存后保留）`
- 支持仅拉取免费模型
- 支持**手动添加自定义模型 ID**（模型管理弹窗内输入框）：上游 `/models` 列表滞后或遗漏时（如魔搭 GLM-5.3-Flash），直接填 ID 即可加入并勾选启用；若该 ID 不在上游列表中，添加时即红色标注并提示
- 添加前可点 **🔗 测试**：对填写的模型 ID 发一次最小请求，直接显示 ✅ 可用（含延迟）/ ❌ 不可用（含错误详情）

### 🔃 上游排序（拖动重排）

- 每张上游提供商卡片**右上角**有 **⠿** 把手，**平时隐藏、鼠标悬停卡片时淡入**（触屏等无悬停环境常显兜底）
- 按住把手拖动即可重排；拖动中源卡片半透明、落点卡片显示虚线框
- 松手立即 `POST /api/providers/reorder` **写回 `providers.json`**，刷新 / 重启都保持
- 服务端只按"现有提供商里确实存在的名字"重排：多出的名字忽略、未提到的按原相对顺序追加到末尾（界面有增删时不会丢条目）
- **顺序的语义**：它不参与候选排序键，但四项键**完全同分**时由它决定先后；而"尚无转发样本"时四项必然全等（质量分同为中性 0.5、都无样本、延迟同为占位值）⇒ 上游顺序 ≈ **冷启动期的实际尝试优先级**，一旦跑出样本，优先级就交给可用率与延迟

### 📦 管理输出模型

- 查看本网关对外暴露的所有模型 ID（格式 `提供商名-模型名`）
- 一键复制，方便填入第三方工具

### 📈 消耗统计

- 按近24小时 / 7 天 / 30 天统计请求数、输入/输出/合计 Token
- 按"渠道·模型"维度明细展示
- 「最近调用记录」内存为空时自动从 `usage.jsonl` 重建（重启后不再空白）

### 🌐 代理设置

- 标题栏 ⚙️ 按钮打开设置弹窗，可配置网关访问上游时的代理
- 四种模式：**不使用代理** / **跟随系统** / **HTTP** / **SOCKS5**
- 「跟随系统」读取 Windows 系统代理设置（注册表 `HKCU\...\Internet Settings`，**只读不写**），自动拼装代理地址
- HTTP / SOCKS5 可手填地址与端口；保存后立即重建连接池生效，无需重启
- SOCKS5 依赖 `httpx[socks]`（打包时需 `--hidden-import socksio`）

### 🛡️ 智能容灾

- **停用不限时 + 后台探活**：被熔断 / 拉黑的组合不会"到点自动放行"，唯一解除条件是**探活成功**或**真实转发成功**
    - **熔断**（临时性错误）：转发连续失败 **5** 次 → 停用；5 分钟后打第一次探活，之后每 **2 分钟**一次
        - 探活连续失败 **5** 次 → **静默 20 分钟**（其间完全不探活），静默结束回到每 2 分钟一次
        - 当天第 **5** 次进入静默 → **直接停用到当天零点**，彻底停止探活（单组合硬上限：**25 次探活 / 约 2 小时 5 分**）
    - **拉黑**（永久性错误）：`400/401/402/403/404/410/422` 命中 **1 次即停用**；触发即计时，每 **10 分钟**探活一次
        - 探活成功 → 立即解禁；连续探活失败 **5** 次（约 **50 分钟**）→ 停用到当天零点，不再探活
- 停用粒度是**组合级**（`上游 × 模型`）：停用 `AMD · GLM-5.2` 不影响同上游的其它模型，也不影响别家同名的模型
- 停用是**兜底式**：被停用的候选只降到候选末尾、不会从列表移除，只有全部候选都被停用时才轮到它们，永远不会出现"无可用模型"
- 候选排序四层：**停用兜底** → **健康优先**（近 120 秒内临时失败过的渠道垫底）→ 可用率降序 → 平均延迟升序（流式首包 TTFB）；四项完全相同时按**上游卡片顺序**（`providers.json` 顺序）兜底 —— 尚无样本时四项必然全等，此时顺序即实际尝试优先级，可用卡片拖动把手调整
- 可用率与延迟来自**转发结果被动更新**，不额外探测上游；无样本的候选给中性分（不会乐观地排在已验证可用的渠道之前）
- **探活只探"已停用"的组合**：健康组合一个请求都不发；没有停用项时后台零请求
    - 探活请求只写 `gateway.log`，**不写 `usage.jsonl`、不进调用记录**，不污染用量统计
    - 界面上：稳定性表格的行内停用徽标带**实时倒计时**，**点击徽标即探活该组合**；工具栏「探活停用项」一键探活全部停用组合
- **单次请求最多尝试 6 个候选**，避免把时间耗在一长串失效渠道上（原来会把整组扫完才报错）
- 流式转发中断时自动切换下一个候选模型继续输出，用户无感
- 路由组全失败自动重试一轮，两次均失败才返回错误
- 调用记录会带上游返回的原始原因（如 `HTTP 404 · Model GLM-5.2 is not available`），便于直接定位是哪个渠道的哪个模型失效

## 🚀 使用方式

### 方式一：PC版exe（推荐普通用户）

1. 下载 `API-N1-Router.exe`：在仓库 Release 获取
2. 双击运行 → 首次显示免责声明 → 点"我已阅读并同意"
3. 自动打开程序窗口，首次会自动生成配置
4. 在"上游提供商"里点“一键配置”或者"+ 添加提供商"，填入你的 API 信息
5. 把程序显示的 **Base URL** 和 **API Key** 填入任何支持 OpenAI 格式的工具即可使用

> PC版无需安装 Python 环境，开箱即用。关闭窗口后程序会最小化到系统托盘后台运行，右键托盘"退出"可彻底关闭。程序同目录会自动生成配置文件。

### 方式二：网页版（自行部署）

适合想在服务器上部署、或本地有 Python 环境的用户。

#### 1. 安装依赖

```bash
pip install -r requirements.txt
```

#### 2a. 以桌面窗口模式运行（带原生窗口）

```bash
python app.py
```

会启动服务并弹出一个原生桌面窗口（需额外安装 `pip install pywebview`）。

#### 2b. 以纯网页模式运行（适合服务器）

```bash
python -m uvicorn app:app --host 0.0.0.0 --port 8000
```

然后在浏览器访问 `http://你的服务器IP:8000`。

> 服务器部署建议用 `uvicorn` 或 `gunicorn`，可配合 nginx 反向代理。网页版和桌面版功能完全一致，只是运行形态不同。

#### 3. 配置提供商

首次启动会自动生成 `config.json`（含本地密钥）。在管理面板的"上游提供商"里添加你的 API，或直接编辑 `providers.json`。

## ⚙️ 配置文件说明


| 文件                 | 作用    | 说明                                    |
| ------------------ | ----- | ------------------------------------- |
| `config.json`      | 本地密钥  | 首次启动自动生成，含 `local_api_key`            |
| `providers.json`   | 上游提供商 | 配置你的 API 渠道（名称、Base URL、API Key、模型列表） |
| `models_meta.json` | 模型元数据 | 模型别名、上下文长度、描述                         |
| `routers.json`     | 路由配置  | 自定义路由组（在面板里配置，自动生成）                   |
| `history.jsonl`    | 巡检历史  | 自动保留 30 天                             |
| `usage.jsonl`      | 消耗统计  | 自动保留 30 天                             |


可参考仓库里的 `config.example.json` 和 `providers.example.json`。
